# RAG 准确率优化指南

## 一、检索算法演进

### 1. 朴素关键词匹配（v1）
每个关键词在文档中是否存在 → 匹配数/总关键词数 = 分数。
**问题**："RAG是什么"中"是""什么"是停用词，匹配所有文档。Milvus文档提到一次RAG = 100%。

### 2. 停用词过滤 + TF-IDF（v2）
过滤掉50+中英文停用词，用IDF加权。  
**问题**：只剩"RAG"一个关键词时，任何匹配都是100%。

### 3. BM25 + 多策略融合（v3 — 当前版本）

**BM25 核心公式**：
```
score(D,Q) = Σ IDF(qi) × f(qi,D) × (k1+1) / (f(qi,D) + k1×(1-b+b×|D|/avgDL))
```

**三个关键参数**：
| 参数 | 值 | 作用 |
|------|-----|------|
| k1=1.5 | 词频饱和 | 出现1次≈出现50次不被线性放大50倍 |
| b=0.75 | 长度归一化 | 短文档中的匹配比长文档更重要 |
| IDF | 逆文档频率 | 稀有词（如Milvus）比常见词（如系统）权重高 |

**增强策略**：
| 策略 | 加成 | 说明 |
|------|------|------|
| 精确短语匹配 | +30% | "RAG是什么"完整出现在块中 |
| 文档名匹配 | +25% | 关键词在文件名中出现 |
| 高密度奖励 | +10% | 每1000字符关键词出现>10次 |
| 最低匹配阈值 | 40% | 至少匹配40%的非停用词 |

## 二、为什么 BM25 能区分"RAG文档"和"提到RAG的文档"

| | Milvus块 | RAG块 |
|------|----------|-------|
| "RAG"出现次数 | 1次(tf=1) | 20次(tf=20) |
| BM25 tf饱和 | tf×3.5/(1+1.5×(1-0.75+0.75×len/avg)) ≈ 0.6 | ≈ 1.2 |
| 文档名匹配 | ❌ Milvus不含RAG | ✅ +25% |
| 精确短语 | ❌ | ✅ +30% |
| **最终分数** | ~0.35 (35%) | ~0.95 (95%) |

## 三、进一步提升准确率的方向

### 短期（浏览器端可实现）
- N-gram匹配：同时匹配"向量数据库""语义搜索"等短语
- 标题加权：块开头100字符 ×1.5权重
- 位置惩罚：块末尾的关键词匹配 ×0.8

### 中期（需服务端）
- Embedding语义检索：BGE-M3向量化 → 余弦相似度
- 混合检索：BM25 + 向量检索 → RRF融合
- 重排序：Cross-Encoder重排序Top-20

### 长期（生产级）
- 查询意图分类：事实型/概念型/操作型 → 不同检索策略
- HyDE：LLM生成假设答案 → 用假设答案embedding检索
- 多路召回：关键词+语义+知识图谱 → RRF融合
