# LLM 平台 · 架构说明（面试讲稿）

> 这是给面试官讲解系统思考的主线文档。每一层、每一个体系都对应代码里真实存在的模块。

---

## 一、一句话定位

一个 **分层清晰、可落地、可演进** 的生产级 LLM 应用平台骨架。核心叙事是——**用工程确定性驾驭模型不确定性**。

---

## 二、十层水平分层（依赖方向）

```
api → services → domain → [repositories / infrastructure]
                        ↘ agents → mcp → [memory / rag]
                          security / observability / resilience / evaluation 横向
                          core 最底层，被所有层依赖，不依赖任何层
```

| 层 | 目录 | 职责 | 面试可讲点 |
|---|---|---|---|
| **core** | `src/core/` | 异常体系 + 工具契约 + 共享类型 | 最底层，不依赖任何层 |
| **api** | `src/api/` | 路由 + 依赖注入 | 统一响应包 + 鉴权 |
| **agents** | `src/agents/` | Agent 模式 + 编排 + 工具 | ReAct/PEV/7 编排 |
| **mcp** | `src/mcp/` | MCP Server/Client | Agent 统一接入资源 |
| **memory** | `src/memory/` | 五层记忆 | STM/LTM/Episodic/遗忘曲线 |
| **rag** | `src/rag/` | 全链路 RAG | chunk/embed/检索/生成 |
| **repositories** | `src/repositories/` | ORM + 持久化 | 禁止 ORM 穿透 |
| **infrastructure** | `src/infrastructure/` | config/redis/broker | 基础设施 |
| **security** | `src/security/` | auth/RBAC/ABAC/PII | 零信任 |
| **observability** | `src/observability/` | metrics/tracing/health | 上帝依赖，零业务依赖 |
| **resilience** | `src/resilience/` | 分层超时/重试预算/恢复 | 韧性专章 |
| **domain** | `src/domain/` | 对话/上下文/token/prompt | 领域模型 |
| **harness** | `src/harness/` | Agent 安全护栏 | ★ 三大体系 |
| **herms** | `src/herms/` | 自进化闭环 | ★ 三大体系 |
| **ragas** | `src/ragas/` | RAG 质量评估 | ★ 三大体系 |

**为什么分层能防循环依赖**：依赖方向单向（`api→services→domain`，`domain 不依赖框架`，`repositories 不穿透 ORM`），任何一层不能反向 import。这从结构上杜绝了 God Class 和循环依赖。

## 三、三大生产级思考体系（面试重点）

### 3.1 Harness 层 —— Agent 安全护栏

**解决什么**：LLM 是不确定性的，Agent 循环若不套硬护栏，会无限循环、刷爆 Token 成本、执行危险操作。

**核心思想**：用**代码确定性**去约束**模型不确定性**。

| 护栏 | 机制 | 代码 |
|---|---|---|
| 最大迭代 | 硬上限 max_steps | `harness/guard.py` |
| 成本上限 | Token/金额预算熔断 | `harness/guard.py` |
| 输出校验 | 独立校验器（禁止 LLM 自判） | `harness/verify.py` |
| 高危工具拦截 | 写操作需审批 | `harness/guard.py` |
| 业务事务 | Prepare/Commit/Abort + 回滚栈 | `harness/transaction.py` |
| 快照回放 | 每步状态落库 | `harness/checkpoint.py` |

**面试金句**："子 Agent 欺骗主编排器是真实攻击面，所以 Verify 不能交给 LLM 自己判定——我用独立的确定性校验器。"

### 3.2 Herms 层 —— 评估驱动的自进化闭环

**解决什么**：系统上线后如何越用越好、安全迭代。

**H-E-R-M-S 逐字母拆解**：

| 字母 | 含义 | 落地 | 代码 |
|---|---|---|---|
| H | Human 人类监督 | 人工审批/高风险复核 | — |
| E | Evaluation 评估 | 在线评估 + 六维 + RAGAS | `ragas/` |
| R | Rollout 灰度 | 流量染色 + 多版本 | `herms/grayscale.py` |
| M | Monitoring 监控 | 拒答率/引用率/负反馈率 | `herms/drift_monitor.py` |
| S | Self-improvement | 失败回灌 + 自动调参 | `herms/self_improve.py` |

**防"自更新奖励黑客"**：自更新必须有护栏，不能放任系统自我奖励跑偏——`SelfImprover` 只在独立评估确认提升时才应用变更。

### 3.3 RAGAS 层 —— RAG 质量评估

**解决什么**：用标准化指标量化 RAG 质量，而不是拍脑袋说"检索挺好"。

| 指标 | 度量什么 |
|---|---|
| Faithfulness | 答案忠于上下文（防幻觉） |
| Answer Relevancy | 答案切题 |
| Context Precision | 检索到的文档相关 |
| Context Recall | 相关文档都被检索到 |
| Answer Correctness | 答案事实正确 |

配套：Golden Dataset（≥100 例、污染检查）+ 漂移监控 + 评测可视化。

## 四、韧性专章（文档第 11 部分）

| 机制 | 核心原则 | 代码 |
|---|---|---|
| 分层超时 | 内层 < 外层 | `resilience/timeout.py` |
| 重试预算 | 防重试风暴 | `resilience/retry_budget.py` |
| 断点恢复 | 恢复前一致性校验 | `resilience/recovery.py` |
| 资源 TTL | 防泄漏 | `resilience/reclaimer.py` |

**面试金句**："任何外部调用必须显式超时，任何重试必须带幂等键，任何资源必须带 TTL。"

## 六、高并发/亿级的诚实边界

**关键认知**：高并发/亿级是运维 + 基础设施的结果，不是纯代码写出来就成立的。

- **真实跑通（Phase 1）**：熔断/限流/降级/缓存/异步/背压/分层超时重试/无状态扩展设计
- **蓝图（Phase 2/3/4）**：分库分表/多活/GPU 集群/压测（见 `docs/亿级演进蓝图.md`）

**面试话术**："当前是 Phase 1 MVP，单机可验证的机制全部真实跑通；亿级是 Phase 4 的演进目标，我已经设计了分库分表/多活/GPU 集群/压测方案，真实验证需要真实基础设施。"
